# Shernice - เว็บแอปพลิเคชันร้านตัดรูป ROV (Arena of Valor)

เว็บแอปพลิเคชันร้านตัดรูป ROV คมชัดระดับพรีเมียม สไตล์น่ารัก อบอุ่น ทันสมัย (Mobile-First Responsive) พร้อมระบบจัดการคิวอัตโนมัติ ระบบตรวจสอบสลิปโอนเงินป้องกันสลิปซ้ำ ระบบสะสมแต้มแบบเงื่อนไขรีวิว และระบบหลังบ้าน (Admin Dashboard) ครบวงจร

### 4. ระบบจัดคิว (Queue System)
- สร้างหมายเลขคิวอัตโนมัติในรูปแบบ `"SN" + ตัวเลข 3 หลัก` (เช่น `SN001`, `SN002`, ... และขยายต่อได้เกิน 999 เช่น `SN1000`)
- ลำดับต่อเนื่องตลอดไป **ไม่มีการรีเซ็ตรายวัน** และ **ไม่หายแม้มีการลบออเดอร์เก่า**
- ปลอดภัยจากการส่งข้อมูลพร้อมกัน (Concurrency Safe) ด้วย Atomic Database Transaction
- **ป๊อปอัปยืนยันการรับคิว**:
  - แสดงเลขคิวขนาดใหญ่: `"คิวของลูกค้าลำดับที่ SN001"`
  - ข้อความเตือน (Verbatim):
    > *"สำคัญ! รบกวนลูกค้าคัดลอกเลขคิวไว้ส่งให้ทางแชทร้าน หากไม่ส่งให้ร้าน ทางร้านไม่รันคิวให้ทุกกรณีนะคะ"*
  - ปุ่ม **"คัดลอกเลขคิว"** และปุ่มนำทางไปหน้าชำระเงิน
  - ดีไซน์การ์ดตั๋วสวยงาม แคปเจอร์หน้าจอง่าย
- **หน้าเช็คคิว (/queue)**: ค้นหาด้วยเลขคิว แสดงสถานะ `รอชำระเงิน` / `กำลังดำเนินการ` / `เสร็จแล้ว`

### 5. ระบบชำระเงิน (Payment)
รองรับ 3 ช่องทางหลัก:
1. **พร้อมเพย์**:
   - ข้อความ: *"คิวอาร์นี้ล็อคยอดไว้อยู่แล้ว ลูกค้าบันทึกรูปคิวอาร์แล้วสแกนจ่ายได้เลยค่ะ"*
   - แสดงภาพ QR Code (ไม่อนุญาตให้แสดงเลขพร้อมเพย์เป็นข้อความตามเงื่อนไข)
   - ชื่อบัญชี: `"น.ส.ปิ่นจุฑา ฟุ้งสกุล"`
2. **กสิกร**:
   - ข้อความ: *"รบกวนโน้ตสลิปทุกครั้งที่ใช้บริการ และตรวจสอบชื่อบัญชีก่อนกดโอน โอนผิดทางร้านไม่รับผิดชอบทุกกรณี"*
   - แสดงภาพการ์ดบัญชีธนาคาร (ชำระผ่าน QR สแกนเท่านั้น ไม่แสดงเลขบัญชีเป็นข้อความ)
   - ชื่อบัญชี: `"น.ส.ปิ่นจุฑา ฟุ้งสกุล"`
3. **TrueMoney Wallet**:
   - ข้อความ: *"โอนเข้าวอเลตโดยตรง บวกค่าธรรมเนียม 2.- หากยืนยันตัวตนแล้วสแกนจ่ายผ่านวอเลตแบบนี้ไม่บวกเพิ่มค่ะ"*
   - เบอร์วอเลต: `096-269-4483` (แก้ไขได้ในหลังบ้าน)
   - ชื่อบัญชี: `"น.ส.ปิ่นจุฑา ฟุ้งสกุล"`
- **ข้อกำหนดร่วมทุกช่องทาง**:
  - แสดงคำโน้ตสลิป: `"คำโน้ตสลิป"` พร้อมปุ่ม `"คัดลอกคำโน้ตสลิป"` (รูปแบบ: `SN001 คุณ[ชื่อลูกค้า]`)
  - แสดง: `"ซื้อขายกับ Line: @832rjuhx"`

  - อัปโหลดไฟล์ภาพสลิป คำนวณ SHA-256 Hash เพื่อป้องกันการนำสลิปเดิมมาใช้ซ้ำ

### 6. ระบบสะสมแต้ม (Loyalty Point System)
- **เงื่อนไขสำคัญ**: 1 สลิปที่ได้รับการอนุมัติ = 1 แต้ม แต่จะมอบแต้มให้เฉพาะลูกค้าที่มีรีวิวที่ผ่านการอนุมัติแล้วเท่านั้น!
- ป้องกันสลิปเดิมได้รับแต้มซ้ำ
- จัดเก็บบัญชีแยกประเภทแต้ม (Point Ledger: Earned, Redeemed, Adjusted พร้อมเวลาและเหตุผล)
- **หน้าสะสมแต้ม (/points)**:
  - ค้นหาด้วยชื่อหรือเลขคิว พร้อมยืนยันช่องทางและ ID ติดต่อที่ใช้สั่งงาน
  - การ์ดสะสมแสตมป์ 10 ช่อง (เป้าหมาย 10 แต้ม)
  - รายการของรางวัล: *"เมื่อสะสมครบตามเงื่อนไข สามารถเลือกของรางวัลได้"* (ตัวอย่าง: ส่วนลด STK, นฟ, CP, DM)
  - คำอธิบาย: *"สงวนสิทธิ์ให้เฉพาะลูกค้าที่รีวิวให้กับทางร้านเท่านั้น หากสะสมครบมีรางวัลสุดพิเศษให้เลือกเย้อมากก"*
  - ฟอร์มส่งรีวิวให้ร้าน เพื่อปลดล็อกสิทธิ์รับแต้ม
  - แอดมินสามารถปรับแต้มด้วยตนเองได้ในหลังบ้าน

### 7. ระบบหลังบ้าน (Admin Panel)
- เข้าสู่ระบบด้วยรหัสผ่านที่กำหนดเองใน `.env` ก่อนเริ่มใช้งาน (จัดเก็บแบบ Hashed ด้วย Bcrypt และเปลี่ยนได้ในระบบ)
- เมนูการจัดการ:
  - **คิว & บรีฟงาน**: ดูรายการออเดอร์ทั้งหมด ดูบรีฟฉบับเต็ม ค้นหา กรองสถานะ
  - **สลิปชำระเงิน**: ตรวจสอบภาพสลิป อนุมัติ/ปฏิเสธ พร้อมตรวจสอบ Hash
  - **จัดการสินค้า**: เพิ่ม/แก้ไข/ลบสินค้า แก้ไขราคา คำอธิบาย เชิงอรรถ และรูปตัวอย่าง
  - **ลูกค้า & แต้ม**: ดูรายชื่อลูกค้า ยอดแต้มสะสม ปรับแต้ม เพิ่ม/ลด พร้อมบันทึกเหตุผล
  - **อนุมัติรีวิว**: ตรวจสอบรีวิว อนุมัติเพื่อปลดล็อกแต้มสะสม
  - **ช่องทางชำระเงิน**: อัปโหลด QR พร้อมเพย์ ภาพการ์ดกสิกร เบอร์ TrueMoney
  - **ธีม & สไตล์**: ปรับเปลี่ยน Palette สี (Primary, Secondary, Accent, Background, Card)
  - **โปรไฟล์ร้าน**: อัปเดต Bio, ภาพ Avatar GIF, ภาพ Cover GIF, เพลงประกอบ, ลิงก์ Drive/Contact
  - **ความปลอดภัย**: เปลี่ยนรหัสผ่านแอดมิน
  - **Audit Logs**: บันทึกประวัติการทำงานของแอดมินทั้งหมด

## 🛠️ โครงสร้างเทคโนโลยี (Tech Stack)

- **Framework**: Next.js 14 (App Router)
- **Frontend**: React 18, TypeScript, Tailwind CSS
- **Icons & Animation**: Lucide React, Canvas-Confetti, CSS Keyframe Animations
- **ORM & Database**: Prisma ORM with SQLite (Default: Zero-config ในเครื่อง) และรองรับ PostgreSQL / Supabase
- **Authentication**: Signed HTTP-only Cookie with Bcrypt Hashing
- **File Storage**: Local uploads with SHA-256 duplicate detection

## 🚀 วิธีการติดตั้งและรันโปรเจกต์ (Installation & Running)

### 1. ติดตั้ง Dependencies
```bash
npm install
```

### 2. เตรียมฐานข้อมูลและสร้างข้อมูลเริ่มต้น (Database & Seed)
```bash
npx prisma db push
node prisma/seed.js
```

### 3. รันในโหมด Development
```bash
npm run dev
```
เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

### 4. รันในโหมด Production
```bash
npm run build
npm start
```

## ⚙️ ตัวแปรสภาพแวดล้อม (Environment Variables)

ไฟล์ `.env` ประกอบด้วย:
```env
# Database connection string
# ใช้ SQLite ในเครื่อง (Zero-config) หรือเปลี่ยนเป็น PostgreSQL / Supabase ได้ทันที
DATABASE_URL="file:./dev.db"

# ตั้งรหัสผ่านแอดมินของคุณเอง อย่างน้อย 12 ตัวอักษร ก่อน seed ฐานข้อมูล
ADMIN_INITIAL_CODE="ใส่รหัสผ่านเฉพาะของคุณที่นี่"

# กุญแจสุ่มเฉพาะระบบ อย่างน้อย 32 ตัวอักษร (ห้ามใช้ค่าตัวอย่าง)
JWT_SECRET="ใส่ค่าสุ่มเฉพาะของคุณอย่างน้อย 32 ตัวอักษร"
```

### การเปลี่ยนไปใช้ PostgreSQL / Supabase
1. เปลี่ยน `provider = "postgresql"` ใน `prisma/schema.prisma`
2. แก้ไข `DATABASE_URL="postgresql://username:password@host:5432/dbname"` ในไฟล์ `.env`
3. รัน `npx prisma db push` และ `node prisma/seed.js`

## 💡 ข้อสมมติฐานและการตีความในจุดที่โจทย์เปิดกว้าง (Assumptions Made)

1. **การบันทึกสลิปและตรวจสอบสลิปซ้ำ**:
   - ระบบใช้ SHA-256 Hash ของไบนารีไฟล์รูปภาพสลิปที่ลูกค้าอัปโหลด หากลูกค้าส่งไฟล์รูปภาพสลิปเดียวกันในคิวอื่น ระบบจะปฏิเสธการอัปโหลดทันทีพร้อมแจ้งเลขคิวเดิมที่เคยใช้
2. **เงื่อนไขการสะสมแต้ม (Loyalty Gate)**:
   - สลิปที่ได้รับการอนุมัติจะได้ 1 แต้ม แต่มีเงื่อนไขว่าลูกค้าต้องมีรีวิวที่ผ่านการอนุมัติแล้วในระบบ หากลูกค้ายังไม่เคยรีวิว ระบบจะยังไม่มอบแต้มทันที แต่เมื่อแอดมินกดอนุมัติรีวิวของลูกค้ารายนั้น ระบบจะทำการคำนวณและมอบแต้มย้อนหลังสำหรับสลิปที่อนุมัติแล้วให้ทันทีอัตโนมัติ
3. **Form B ("บรีฟงานใส่ลิงก์ต่าง ๆ")**:
   - เนื่องจากบรีฟระบุว่า fields TBD สร้างเป็น configurable placeholder ได้จัดทำฟอร์มที่รองรับการกรอก URL ลิงก์ปลายทาง ชื่อปุ่ม/หัวข้อลิงก์ โทนสีและสไตล์ที่ต้องการ พร้อมหมายเหตุเพิ่มเติม และสร้างเลขคิว SN ในระบบเดียวกัน
4. **การรองรับ GIF และขนาดรูปภาพ**:
   - ทุกส่วนที่รองรับอัปโหลดภาพ (Avatar, Cover Banner, ตัวอย่างงาน) รองรับไฟล์นามสกุล `.gif`, `.png`, `.jpg`, `.webp` พร้อมการแสดงผลแบบ object-cover/object-contain
